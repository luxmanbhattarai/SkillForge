# Infographic Generation

## Purpose

This skill turns data, steps, or comparisons into an infographic a
reader can understand at a glance. It covers choosing the right chart
type, verifying the data, laying out the visual hierarchy, writing
accurate labels, and exporting a readable, accessible graphic.

## When to Use

- A task asks for an infographic, data visualization, or chart graphic.
- An article, report, or presentation needs a visual summary of numbers.
- A process, timeline, or comparison needs to be shown rather than
  described in paragraphs.
- A social post needs a data graphic that stands alone.
- An existing infographic has wrong data, an unreadable layout, or a
  misleading chart.

## When Not to Use

- The task needs a decorative illustration with no data — use
  `ai-image-generation` instead.
- The task needs a photographic hero image — use `blog-featured-images`
  instead.
- The task needs an interactive dashboard or live chart — this skill
  covers static infographic images, not interactive applications.
- The data is not verified — do not build an infographic on unverified
  numbers; verify the data first, then design.

## Prerequisites

- The verified data: numbers, labels, units, and the source of each
  figure.
- The single message the infographic must communicate.
- The placement and dimensions: article embed, social post, slide, or
  print.
- The brand assets: palette, fonts, and logo.
- A design or charting tool the team can use to build the graphic.

## Required Workflow

1. State the single message in one sentence. If the infographic needs
   two messages, it is two infographics.
2. Collect and verify the data: every number, label, unit, and date,
   with its source recorded. Never build on numbers that cannot be
   traced to a source.
3. Choose the chart type that fits the data: bars for comparisons,
   lines for change over time, parts of a whole for shares, and a
   numbered flow for steps.
4. Draft the content as text first: title, chart labels, key figures,
   and the source line. Design starts only after the content is right.
5. Lay out the hierarchy: title, key figure or takeaway, chart, then
   supporting detail, then the source line.
6. Use one chart style per graphic and a limited palette; color must
   encode meaning, not decoration.
7. Label values directly on the chart where space allows, so readers
   do not have to estimate from an axis.
8. Add the data source and the date the data refers to, in small but
   readable text at the foot of the graphic.
9. Export at a size readable in its placement, and check readability
   at the actual display size, including on a phone.
10. Write a text alternative or accompanying data table (see
    `image-accessibility`) so the information is available to readers
    who cannot see the graphic.

## Implementation Standards

- Every number in the graphic traces to a named source, and the source
  and date appear on the graphic itself.
- Charts start bar axes at zero unless there is a stated, defensible
  reason not to; truncated axes mislead readers about differences.
- Labels are complete: units, date ranges, and what each category
  means. A number without a unit is not information.
- Text is real text in the design tool, never generated by an image
  model. Image models garble numbers and labels, so infographic text
  is always set by hand or by a charting tool.
- One message, one chart type, one palette per graphic. Mixed chart
  types and rainbow palettes confuse readers.
- The title states the takeaway, not just the topic: "Starter failures
  peak in week two" beats "Starter failures".
- The exported file is readable at its real display size; if labels
  are unreadable there, simplify the graphic rather than shrinking
  the type further.

### Accessibility

- Every infographic ships with a text alternative: the underlying data
  as a table or a written summary of the findings.
- Do not encode data by color alone: label series directly, use
  patterns or shapes alongside color.
- Text in the graphic is legible at the published size, with 4.5:1
  contrast; body copy lives in the page, not in the image.
- Reading order is logical: a screen-reader user following the text
  alternative gets the same story in the same order.
- Shared baseline: `docs/ACCESSIBILITY-STANDARDS.md` (WCAG 2.2 AA);
  the full audit workflow lives in the `accessibility` skill.

## Best Practices

- Show the data, then the interpretation: the chart first, the
  takeaway second, the detail last.
- Round numbers for display when precision does not matter, and say
  so in a footnote when rounding changes the story.
- Use direct labels instead of legends where space allows; readers
  should not have to look back and forth.
- Keep the number of data points small: five to seven categories is
  usually the limit for a readable chart.
- Design for the smallest placement first; a graphic readable on a
  phone will be readable everywhere.
- Keep the source data file with the design so the graphic can be
  updated when the numbers change.

## Security Considerations

- Do not publish data the organization does not have the right to
  share: internal figures, personal data, or data under a restrictive
  license.
- Aggregate or anonymize personal data before visualizing it; a chart
  must not expose individual records.
- Verify the data source before publishing; a graphic built on a
  fabricated or misread source spreads misinformation with the
  authority of a chart.
- Do not include credentials, internal URLs, or private identifiers
  in chart labels, footnotes, or file metadata.
- Check that any third-party chart or icon library used in the design
  is licensed for the intended use.

## Performance Considerations

- Export infographics as compressed PNG or WebP; text-heavy graphics
  need a format that keeps edges sharp.
- Keep the file size reasonable for the placement; a multi-megabyte
  infographic slows the page it is embedded in.
- Prefer vector output (SVG) when the placement supports it, so the
  graphic stays sharp at any size and text stays selectable.
- When the graphic is embedded in an article, give it explicit
  dimensions so the page layout does not shift while it loads.

## Common Mistakes

- Building on unverified numbers — verify every figure against its
  source before designing.
- A truncated bar axis that exaggerates a small difference — start
  bars at zero.
- Too many data points in one chart — split the graphic or drop the
  least important categories.
- Using an image model to render the graphic — models garble numbers
  and text; build charts with a charting or design tool.
- A title that names the topic but not the takeaway — the title
  should state what the reader should conclude.
- No source line — a chart without a source cannot be trusted or
  checked.
- Text too small to read at the real display size — simplify the
  graphic instead of shrinking the type.

## Examples

Example content draft before any design work:

```text
Title: Starter failures peak in week two
Message: Most new sourdough starters fail in the second week, when
feeding schedules slip.
Data (source: site reader survey, n=214, January 2026):
  Week 1: 18% of failures
  Week 2: 47% of failures
  Week 3: 22% of failures
  Week 4+: 13% of failures
Chart: horizontal bars, one per week, values labeled.
Footnote: Source: site reader survey, n=214, January 2026.
```

Example text alternative for the published graphic:

```text
Infographic: "Starter failures peak in week two." Bar chart of when
reader sourdough starters failed: week 1, 18%; week 2, 47%; week 3,
22%; week 4 or later, 13%. Source: site reader survey, 214
respondents, January 2026.
```

Example export checklist for the finished file:

```text
Format: PNG, 1200 px wide
Check: title readable at 600 px wide; labels readable on a phone
Alt text: short description plus a link to the data table below
Source line: present on the graphic
```

## Validation Checklist

- [ ] The single message is stated in one sentence.
- [ ] Every number traces to a named source, with the date recorded.
- [ ] The chart type fits the data (bars, lines, shares, or flow).
- [ ] Axes, units, and labels are complete and honest.
- [ ] All text was set by hand or by a charting tool, not by an image
      model.
- [ ] The source line and data date appear on the graphic.
- [ ] The graphic is readable at its real display size, including on
      a phone.
- [ ] A text alternative or data table accompanies the graphic.
- [ ] Accessibility: data available as text/table; series not encoded by color alone.

## Expected Deliverables

- The final infographic file at the target size.
- The verified data table with sources and dates.
- The content draft: title, labels, and footnote text.
- The text alternative or accompanying data table for accessibility.
- The source design file location, for future updates.
