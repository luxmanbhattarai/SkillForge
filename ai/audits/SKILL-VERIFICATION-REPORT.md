## 3. Methodology and provenance

### How each status was determined

- **226 skills (the v1.0.0 library)** were audited in Phase 3 against official vendor documentation (see `ai/audits/TECHNICAL-ACCURACY-AUDIT.md`). That audit's per-skill table records 204 Verified, 16 Verified with limitations, 6 Needs correction. Errors found in original skills were fixed in place during Phase 3; errors found in upstream skills were recorded, not edited.
- **51 skills (added in Phase 4)** were audited in Stage C by the same method (see `ai/audits/SKILL-AUDIT-MATRIX.md`): 51/51 audited, 60 findings (0 Critical, 3 High, 11 Medium, 38 Low, 8 Informational), 50 verified and 1 verified-with-limitations (`platform-social-images` — Meta sharing docs returned 403 during verification).
- **1 status changed after the audits (A3-01 override):** `link-building` was "Verified with limitations" in the Phase 3 table solely because of 6 broken relative links to `../../tools/integrations/...`. The `tools/` directory was imported in Phase 4 (commit `caf1f32`) after the Phase 3 audit, so all 6 links now resolve (all 6 target files verified on disk 2026-11-21; `npm run validate` emits no warning for the skill). Phase C promoted it to `verified` with a dated, reasoned override — see §4.
- **Reconciliation:** 204 + 50 + 1 (A3-01) = **255 verified**; 16 + 1 − 1 = **16 verified-with-limitations**; **6 needs-correction**; **0 unverified**. Total 277. The arithmetic closes exactly.

### What the audit cross-check enforces

`scripts/validate-registry.mjs` (`npm run check:registry`) cross-checks every `sources/verification-status.json` entry against the Phase 3 audit table (`ai/audits/TECHNICAL-ACCURACY-AUDIT.md`, section "Per-skill status table", 226 rows parsed):

- A sidecar/audit-table disagreement is a **hard error** (exit code 1) — unless a dated override exists in `AUDIT_OVERRIDES`.
- An override replaces the audit table's expectation for that one skill only, and is itself enforced: if the sidecar no longer matches the override status, that is an error ("stale override"), not a silent pass.
- An override for a skill the audit table does not list is flagged as a warning (stale/mistyped override).
- The Phase 3 audit table is a historical record and is never edited; post-audit re-labels go through overrides only.

At HEAD, the cross-check passes with exactly one warning: the A3-01 override notice for `link-building`. The 51 Stage C skills are not in the Phase 3 table (they did not exist at audit time); their statuses rest on `SKILL-AUDIT-MATRIX.md` and are covered by the registry's verification-coverage check (every registry skill must have a sidecar entry, and vice versa — 277/277 both ways, 0 disagreements between registry status and sidecar status).

### A3-02 note restoration

Phase A finding A3-02 found 17 verification notes truncated at exactly 160 characters (ending in `...`), including all 6 needs-correction notes — the machine-readable record of *what correction is needed* was lossy. Phase C restored the full note text from the audit detail table. Verified at HEAD: **0 notes end in `...`**, **0 notes are exactly 160 chars**, 23 notes total (16 with-limitations + 6 needs-correction + the `link-building` resolution note). The full notes are reproduced verbatim in §1.

## 6. Limitations — what this verification does NOT prove

- **It does not re-verify technical accuracy skill-by-skill against live vendor documentation in this mission.** The statuses rest on the Phase 3 audit (2026-11-20) and the Stage C audit (2026-11-20), plus the automated cross-check that the machine-readable record agrees with those audits. Claims verified on 2026-11-20 can drift as vendors ship releases; this report proves the record is internally consistent and faithfully reflects the audits, not that every claim is still true today.
- **It does not prove the upstream skills are correct** — only that their known defects are recorded. The 6 needs-correction skills contain real errors (broken links, a non-running code example, stale version claims); they are marked, not fixed, because the fix venue is upstream.
- **It does not cover agents or workflows** (24 agents, 16 workflows exist in the registry; this report is skills-only).
- **It does not re-run behavioral evals or the quality scorer**; those are separate checks (`npm run evals`, `npm run score`).
- **The audit cross-check only covers the 226 Phase 3 skills.** The 51 Stage C skills are covered by the registry coverage check (entry exists, status is a valid value) but not by a table cross-check, because no equivalent machine-parseable Stage C table exists in the repo.
- **Version pins are dated 2026-11-20** and will drift on normal release cadence; the Railway 2026-12-01 cutoff (A3-04) and Prisma 8 GA are the nearest known drift events.
